The problem

Software factories ship fast. They still skip the product work.

Give an agent a prompt and it codes. That covers one job: typing. A real team does more before anyone opens an editor. Someone defines what is out of scope. Someone checks the plan for holes. Someone picks the interface before the code locks it in.

Without those roles you get the usual failure set: scope creep, plans nobody questioned, features that should not exist, and tests added after the fact.

Factory pipeline

prompt → code → done

Fast. One role. No memory of why a decision was made.

Stelow team

shape → critique → approve → interface → scope → build → audit

Slower at the start. Fewer rewrites at the end.

How it works

Measure three times, cut once.

Three phases, 17 stages. You set two dials at the start and the workflow follows them. Type /sw-start "what you want" and it asks, shapes, reviews, then builds.

1 · Shape

Write down the bet

IN/OUT boundaries, appetite, risks. Tech preview reads the codebase first so the proposal fits what exists. No code yet.

2 · Review

Argue before building

Fresh-context reviewers pick the plan apart. You approve the product spec and the interface direction in a visual gate, with receipts on disk. Review mode sets how much waits for you: Auto runs untouched, Full gates spec, interface, scopes, and plan.

3 · Build

Hand off typed scopes

Feature, spike, optimize, and test scopes run in dependency order under acceptance contracts. Audit closes the loop or opens new scopes.

Appetite: how deep to prepare

  • Lean: one idea, 1–2 scopes, one interface suggestion.
  • Core: a normal feature, 3–5 scopes, 3 directions plus a hybrid.
  • Complete: risky work, 8–15 scopes, 5 directions plus a hybrid.

Review mode: how much you check

  • Auto: no gates. For throwaway spikes.
  • Spec gate: one approval before tech planning.
  • Full: spec, interface, scopes, and tech plan all gated, plus an optional code-diff review.

What changes

The parts factories leave out.

Each one maps to a role on a product team. Together they keep small decisions from becoming rewrites.

Shaped bets, not wishlists

Every proposal states what is in and what is out, the appetite it must fit, and the risks. A fit check runs before planning continues. If it does not fit, the scope gets cut. The budget never grows to fit the scope.

Reviewers with fresh eyes

Plans go to parallel reviewers who never see each other's notes. They check flows, states, data, feasibility, and assumptions. The author cannot review its own work and pass.

Gates with receipts

Spec, interface, tech plan, and diff each get a visual approval, and each approval writes a receipt under .stelow/approvals/. No receipt, no advance. Oversight is a dial, not a lottery: Auto runs untouched, Full gates everything.

Typed scopes under contract

Work breaks into feature, spike, optimize, and test scopes with dependencies, acceptance criteria, verify commands, and stop rules. Spikes come first when the unknown is large. A scope closes only when its criteria pass.

Audit that closes the loop

After execution, gaps sort into fixed, documented, or escalated. Escalated gaps become new scopes instead of fading. The run ends with a SHA-256 audit trail, and strict mode refuses to seal it while registered output is missing.

Tech talks back early

Before shaping, a preview reads the codebase for constraints. Before planning, recon maps what the change touches. An alignment check compares the tech plan against the spec while edits are still cheap.

Two ways to run it

Host-agnostic at the core. Visual in bb.

Stelow runs as a visual plugin inside bb: board, inbox, and workers in one place. Underneath, the same 28 skills and the scripts/stelow helper stay portable to any agent that reads skills. No lock-in either way.

Path A · recommended

bb desktop + Stelow plugin

Board, inbox, blocking questions, presets, and a worker CLI. The plugin vendors all 28 skills and syncs them from this repo on a schedule.

  • Build cards: Triage → Analyse → Plan → Execute → Review → Done
  • Research cards across the strategy library; Explore cards for one-shot techniques
  • Approvals write portable receipts; audit binds to the exact commit
  • GitHub issues can seed inbox drafts; done cards can comment back
  • Skills stay current: vendored copies auto-sync from this repo on a schedule

Still early

Worth knowing before you start.

Built in public, pre-1.0

Public line is 0.x. Workflow contracts and skills can change before 1.0. Old 1.x tags are internal milestones, not stability claims. Found a rough edge? Open an issue: plugin repo for anything practical (board, workers, install), upstream repo for methodology (stages, strategies, skills).

Depth costs tokens

Complete appetite with full gates writes long specs. For a typo fix, pick Lean with Auto and skip the ceremony.

Git URL today, marketplace soon

The plugin installs from git while marketplace approval is pending. Pin a release with @vX.Y.Z for fixed installs; updates arrive via bb plugin update stelow.
