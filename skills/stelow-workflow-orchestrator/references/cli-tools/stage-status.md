# Stage Status Helper

> Human-readable stage commands. These are conversational gestures the user
> types — the entry/router skills interpret them. They never bypass the
> transition contract: every move validates against `transitions.md`.

---

## Commands

| Command | Description |
|---------|-------------|
| `/sw-setphase phasename=<slug>` | Set current stage by canonical slug (e.g. `phasename=shape`) |
| `/sw-next` | Advance to the next valid stage |
| `/sw-status` | Show workflow status |

---

## Canonical Stages (17, pipeline order)

| Stage | Description |
|-------|-------------|
| triage | Inbox Triage — auto if list detected |
| select | Item Selection — after triage |
| setup | Project Setup — stage selection, safe-change |
| context | Strategic Context (optional) |
| shape | Shape Up — spec-product output |
| critique | Product Critique |
| gate | Review Gate (visual review) |
| scope | Scope Adjustment |
| int-gate | Interface Gate (visual review) |
| selection | Interface Selection |
| planning | Tech Planning |
| plan-gate | Tech Plan Gate (visual review) |
| execution | Execution |
| verification | Verification |
| diff-gate | Code Diff Gate (visual review) |
| audit | Final Audit |

Stage order, transitions, and gate rules live in `stages.yaml`
(`transitions.md` is its generated mirror). This table follows that order;
if they ever disagree, `stages.yaml` wins.

---

## Examples

```bash
# Show current status
/sw-status

# Set to Shape stage
/sw-setphase phasename=shape

# Advance to next stage
/sw-next
```

## ASCII Status

For detailed ASCII status in chat, the skill outputs:

```
┌─────────────────────────────────────────┐
│ ◆ Workflow: Snake Game                  │
│   shape (in-progress)                   │
├─────────────────────────────────────────┤
│   triage       ● Done                   │
│   select       ● Done                   │
│   setup        ● Done                   │
│   context      ○ Skipped                │
│   shape        ◆ current                │
│   critique     ○ Pending                │
│   ...                                    │
└─────────────────────────────────────────┘
```

This is generated by the skill at the start of each stage.

## Auto-Advance vs Manual

**Auto-advance (default):** the LLM advances via the stage transition
command and proceeds to the next stage without stopping. State is never
hand-edited — transitions validate every move.

**Manual (paused/error recovery only):** Use `/sw-next` or `/sw-setphase`
with a canonical slug from the table above.

**Reshape cycle (planning → shape):** When tech planning discovers a blocking constraint (`planning:15`), the workflow resets to Shape via `/sw-setphase phasename=shape`. The blocking constraint is saved to `context/blocking-constraints.md` and automatically consumed by `shape:10` when the new cycle starts. This reuses the existing `/sw-setphase` mechanism — no new command.
